# Testing Strategy

> 🔒 Frozen contract · schema v66 (app v0.0.5) · current through Milestone 2 (layout: flex, hug, grow, shrink, wrap+align, grid (+rows/auto/hug/spans/flow/placement), constraints, absolute + per-side margins) + M3 render-model extraction + viewport culling + ellipse/line/path node types + Canvas backend + effects + M4 pan/zoom + box-select + DOM-free handle picking + rotate + live Canvas backend + snapping/guides (move + resize) + rulers + canvas images + group snapping/rotate. Suites: `src/core/tests/document.test.ts` (1586) + `src/renderer/RenderModel.test.ts` (84) + `src/renderer/emitCanvas.test.ts` (60) + `src/renderer/emitSVG.test.ts` (8) = 1745 tests.

## Philosophy

The engine's correctness lives in the **core** (document, actions, dispatcher, history,
serializer) — the layer every other layer trusts. That layer is deterministic, pure,
and has no DOM, so it is tested exhaustively with fast unit tests. The renderer's
**pure model** (`buildRenderModel → DisplayList`) is DOM-free too and unit-tested the same
way; the **Canvas backend** (`emitCanvas`) is unit-tested via a recording-mock ctx (its call
sequence IS its output). The **GPU backend** is split so the same rule holds: everything that
turns a shape into numbers (`itemTriangles`, `shapeToWorldRings`, `parseColor`, `viewMatrix`, and
`geometry/Tessellate` beneath them) is pure and tested in the `node` env; only the buffer uploads
and draw calls need a GPU. Only the DOM shims — `emitSVG`'s output, the `renderSVG`/`renderCanvas`/
`renderWebGL`/`renderScene` wiring, and pixel-level parity between the three — stay validated by targeted browser
smoke tests (the Canvas backend was live-verified end-to-end: background, grid, a drawn rect,
selection overlay, and a clean SVG↔Canvas toggle).

**Milestone 0 bar:** no change to a frozen contract lands without a test. Regressions get
a test that is proven to fail before the fix and pass after (see *regression discipline*).

## Commands

```bash
npm test                                   # jest (ts-jest), 1745 tests
npm run header-claims                      # ADVISORY: module-header sentences with a shelf life
npx tsc --noEmit                           # typecheck the app
npx tsc --noEmit -p tsconfig.test.json     # typecheck the tests too
npm run lint                               # module-header rule (no ESLint dependency)
npm run check                              # typecheck + lint + test + build (the gate)

# Fire a native menu command in the running app (needs the main-process inspector):
npx electron --inspect=9229 dist/electron/main.js --remote-debugging-port=9222
node scripts/menu-command.js --list
node scripts/menu-command.js "Zoom to Fit"
```

- **`scripts/menu-command.js` is how a menu item is verified**, and the indirection is not
  optional. A menu accelerator is handled before the renderer sees the key, so
  `dispatchEvent(new KeyboardEvent(...))` from the page is silently ignored. CDP's
  `Input.dispatchKeyEvent` reaches the browser layer and does work — but only while the window
  happens to be focused, so it fired once here and then quietly stopped, which is the worst
  behaviour a verification tool can have (a green run that means nothing). Clicking the item
  through the MAIN process has no such condition and exercises the real `send()` closure, the real
  channel and the real handler. A missing or disabled item exits non-zero, so a script cannot
  mistake "no such item" for success.

- `npm run lint` also refuses a BACKTICK inside a shader template literal. GLSL lives in template
  strings, so a comment quoting a symbol the way every other comment here does ends the string —
  and it surfaces as a TS1005 pointing at a line of GLSL, which reads as anything but its cause. It
  cost a round twice before the check existed. The check itself was verified by reintroducing the
  bug on purpose: the first version counted matched backtick pairs and passed, because an injected
  backtick simply becomes the closing one.
- Runner: **Jest** via **ts-jest**, `testEnvironment: node` (`jest.config.js`).
- `tsconfig.json` excludes `*.test.ts` from the app build; `tsconfig.test.json` type-checks
  them. Both must be clean.

The last test is the one the extraction exists for — it asserts that what `buildRenderModel` puts on a text shape IS what `resolveTypography` answers for the same style, so the field and the render cannot drift. Five defaults written twice is five chances for one to drift, and the drift is invisible until somebody types into a node that uses that slot. The rest was verified in the running app: the field lands on the node to the pixel at 146% zoom AND under a 30° rotation (its CSS matrix is the node's SVG matrix times the zoom), Delete and the tool keys stay in the field rather than deleting the node being typed into, and both Escape and blur close it |
| **One chord, one owner** | a chord the native menu CLAIMS is handled before the renderer sees the key, so binding it in both places leaves one copy dead and both looking authoritative — which is what I wrote first when adding Zoom to Fit. A test parses every `accelerator:` out of the electron menu and asserts none of them resolves in `resolveShortcut`. Its second half is the part that makes it worth having: it proves the check can SEE a collision (`CmdOrCtrl+D`, `Delete` and `Esc` are all bound in the renderer and must be reported), because a broken accelerator parser would otherwise let everything pass. | **Zoom to fit** | the `contentBounds` fixture went blind first time and is worth the note: a node with a NaN `geometry` never reaches the guard at all, because `computeGeometry` DROPS such a node — so the mutation that deletes the finiteness check survived while the test passed for the wrong reason. A NaN in the TRANSFORM is the reachable case, and the test now asserts reachability (the node is computed, its bounds are non-finite) before asserting the behaviour. The exporter's frame is checked to be the shared bounds plus its own margin, so the two cannot drift back apart. A structural test also pins every `send("…")` in the electron menu against a `case "…"` in App.tsx — this codebase has already shipped TWO dead menu items, where the command was sent and nothing matched it, and neither side's own tests could see a gap that is BETWEEN them |
| **Skinning arithmetic** | the fixture that carries the whole idea is a bone drawn ALREADY ROTATED and still at that angle: it has not moved, so its point must not budge. Using the bone's matrix instead of `posed · rest⁻¹` snaps the artwork onto the axis on the first frame, and only a non-identity rest can tell the two apart — an identity-rest fixture passes either way. The other deliberate ones: a scaled bone carries its point outward from the BONE and not from the world origin (a `posed`-only implementation looks right at the origin); weights of 5 and 5 must deform exactly like 0.5 and 0.5, because exported weights routinely miss 1.0 by a rounding error and trusting them moves the point by the surplus; and a degenerate rest must contribute NOTHING rather than a NaN that spreads through the average. One mutation survives — skipping a zero-weight bone is a fast path contributing `moved * 0`, kept for the 4,225 points of a 64x64 mesh and noted as a measured no-op |
| **Nine-slice (schema 57)** | THE SWEEP IS BLIND HERE, and that is the lesson. All three backends call `nineSliceRects`, so a cross-backend pixel comparison proves they AGREE and can never prove they are right — mutating the shared arithmetic moves the sweep by exactly zero, which was measured rather than assumed. So the expected rectangles are computed BY HAND. Two of those hand fixtures exist only because the first eight were all 9x9: "clamp the vertical against the width" survived twice, and the pair is now in `mutate:dimensions` where that family belongs. What the SWEEP is for is the seven cases where the backends could differ — a tall box, a box smaller than its own border, asymmetric insets, an atlas region, a rotation — all within 1 channel. And what NEITHER could see: setting the field from the inspector did nothing, because `UpdateNodeContentAction` validated `nineSlice` and then built its delta field by field. A geometry test cannot see a gap in the plumbing and a backend comparison cannot either; only asking the document what it now holds can, which is the test that now exists |
| **Skinning (schema 58)** | Ten mutants, ten killed, and the run is scripted rather than remembered. The reachability problem here is sharper than usual: posed can only differ from rest through a step the REST chain does not run, so every fixture keyframes its bone — writing a different number into `geometry` moves BOTH documents and deforms nothing, which is a fixture that passes while testing air. The arithmetic is hand-computed (a bone drawn at x=10 and posed at x=30 is a +20 translation, so the bound corner lands at exactly 20), and each test carries its own falsifiable half — at frame 0 the same node must still be a `core.rectangle`. Three claims no rendering assertion could reach: that a point bound to a bone which moved exactly as its own node did stays PUT (the rest-out/posed-back cancellation), that the rest document is built ONCE for a scene with two rigged meshes rather than once per node, and — the nine-slice lesson applied before it could cost anything — that dragging a control point in the editor keeps its bindings, which only asking the document afterwards can see |
| **Authoring a binding** | Two defects here were reachable only by DRIVING THE APP, and both were invisible to a green suite. Pressing a control point recorded the pick and did not redraw, so the panel appeared on the NEXT event — every other thing a press starts only becomes visible once the pointer moves, so nothing else had ever needed the refresh. And deleting a bone left the points that named it dangling: `Integrity` runs on LOAD rather than per action, so the delete succeeded, the canvas looked right, and the file would not reopen — measured before it was fixed, not assumed. Eighteen mutants across `MeshEdit`, the delete cleanup and the pick, all killed; one started as a SURVIVOR because the fixture bound its nested bone to a mesh that was itself inside the deleted subtree, so there was nothing left to clean and the test passed against a cleanup that only looked at the id it was handed. The end-to-end check is a real click in the layers panel, a real press on the canvas, a real change event on the dropdown, then Save — and reading the FILE, because a panel that reports what it meant to store is the thing being tested |
| **Auto-binding** | Every distance is HAND-COMPUTED, because the arithmetic is the feature: a bone 40x40 at (0,-70) has its joint at (20,-50), 53.85 from the origin, and 1/50 against 1/100 normalises to two thirds and one third. The blend boundary is tested as a PAIR — a second bone at exactly 2x the nearest distance is kept, at 2x plus one unit it is not — because a rule that always kept two would pass the first alone. Ten mutants, ten killed, but one started as a SURVIVOR: every fixture used 0x0 bones, so a bone’s joint and its corner were the same point and "measure to the corner" was invisible. Nine mutants, nine killed, including mirror-before-transpose |
| **The tile brush** | Driven in the RUNNING app as well as in jest, because the half that matters is the wiring: the Map workspace, the panel appearing for a selected tilemap, the sheet picker, a drag, Ctrl+Z, erase and alt-click, with every answer read back out of the SAVED document rather than from the action's return. | **The weight brush** | Every falloff is hand-computed against `(1 − t²)²`: a point 100 away under a 200 radius is t = 0.5, so the profile is 0.5625 and the step is that times the flow. Nineteen mutants, all killed — but FIVE started as survivors and each was a bad probe rather than a missing guard, which is its own lesson. Two mutants were no-ops I had written myself (`t >= 1` vs `t > 1`, where the formula already gives zero); one guard turned out to be genuinely dead and was DELETED rather than documented, because the unchanged-weight check below it already covered the case; and the coalescing probe passed against a first dab that coalesced, because history keys by `ActionId:nodeId` and I had put a GEOMETRY edit in front of it — only a mesh edit on the same node can merge, so only that proves anything. ## The API-surface pin

`src/core/tests/apiSurface.ts` is never executed. It imports every symbol documented
in [API-CONTRACTS.md](API-CONTRACTS.md) and asserts its shape, so `tsc` fails if a
documented export is renamed, removed, or changes signature.

**Its coverage was itself the failure once.** For six schemas — 37 stroke joins/caps,
38 fill rules, 39 animation, 40 depth, 41 mesh, 42 lighting — API-CONTRACTS grew
entries for `Mesh`, `Light`, `Depth`, `Timeline`, `emitWebGL`, `PathBoolean`,
`Resolve`, `StrokeOutline`, `Tessellate`, `ConvexDecompose`, `ShapeHit`,
`ShapeToPath`, `OrientedBox` and `TrackList` while this file imported none of them.
A pin that quietly stops covering new work is worse than no pin, because it reads as
enforcement. **When a module gains a documented export, it gains a line here in the
same commit.** Closing the gap also surfaced a real defect: `GLState` — the return
type of the documented `initGL` and a parameter of the documented `setLighting` —
was not exported, so neither signature could be written down by anyone outside its
own file.

The pin is verified the way every guard here is: by breaking the code on purpose.
Eight documented signatures were mutated — a rename (`surfaceNormal`), a dropped
interface field (`Draw.normals`), a changed return type (`shadowOffset`), an
un-exported type (`GLState`), a widened generic (`applyParallax`) and three dropped
parameters (`resolveRings`, `subdivideTriangles`, `SetLightingAction`) — and each
failed `tsc` **with `apiSurface.ts` named in the error**. That last clause is the
scoring rule: a `tsc` failure that does not name this file is the mutation breaking
its own module, which scores nothing. One mutation was written badly (`T extends
never | {…}` collapses to `T extends {…}` — a no-op) and read as a survivor until
the mutation itself was fixed; the same trap as `if (false)` failing to compile.

It exists because API-CONTRACTS.md drifted in three places during one pass **while the
freeze rule was in force**, and the drift was found by accident. Two mechanisms were
measured against that drift before this one was kept:

| Mechanism | Result |
|---|---|
| Identifier-existence checker over backticked names in docs | caught **0 of 4** — the drift was semantic (`ProjectDocument` still existed, it was just the wrong type), and 5 of 5 hits were false positives |
| Assignability assertion (`expectType<ReadonlyDocument>(…)`) | **passed** even with `getDocument()` reverted to mutable — mutable widens to readonly |
| Generic conditional (`expectNotMutable`) | **fails** correctly: `Argument of type 'ProjectDocument' is not assignable to parameter of type 'never'` |

The lesson is in the middle row: an assertion that only checks *assignability* cannot
detect a guarantee weakening, because weakening is exactly the direction assignability
allows. Guarantees that must not weaken need a conditional generic over the argument's
own type — and the check must be verified by breaking the code on purpose.

**Not covered:** prose describing behaviour that has since changed. Nothing mechanical
catches that; it needs review.

**The pin stopped covering new work, again.** All nine `core/paint` modules — roughly sixty
documented exports, shipped over a single day — had **no line here at all**, while API-CONTRACTS
grew an entry for each. That is the identical failure this file's header records against the
schema-37–42 work, and it is the more dangerous kind: a pin that silently stops growing reads as
enforcement while checking nothing. `_paintSurface()` now covers all nine plus `RasterSurface`
and `PaintSurfaceAction`, and it was verified the required way — widening `worldToSurface` to
return `[number, number] | null | undefined` (a change that still compiles in its own module)
fails `tsc` **with `apiSurface.ts` named**.

The recurrence says the rule needs a trigger, not just a statement: **a new file under `src/core`
is the trigger**. It is the moment the pin is cheapest to extend and the moment it is always
forgotten.

## Mutation testing (verifying the tests, not the code)

"A check is worthless until you have broken the code on purpose and watched it fail"
applies to the whole suite, not just to new regression tests. Every guard added during
the audit campaign was weakened one at a time, with the suite run against each
weakening. A guard nothing notices is not protected.

First pass over 18 guards: **13 killed, 2 survived, 3 unverified** (the mutation string
did not match — *unverified*, not passing). The survivors were real gaps:

| Guard | Why nothing caught it |
|---|---|
| `MoveTool` selection-root filter | the test exercised `selectionRoots` + `computeGeometry` directly, never `MoveTool` — so the CRITICAL parent+child double-apply could have been reintroduced silently |
| coalesce anchored to the last commit | the existing test happened to land on `currentIndex === 0`, so a *different* guard was rejecting the merge; the anchor itself was never exercised |
| legacy → schema-1 normalisation | `LEGACY_SCHEMA` and `SCHEMA_VERSION` are both `"1"` today, so correct and incorrect behaviour are indistinguishable until a future bump — exactly when it would bite |

Three tests were added to close them; the third required making the schema injectable
(`migrateIfNeeded(raw, currentSchema)`) so the future-bump case can be exercised now.

**Three of the mutations were themselves wrong**, and they failed in BOTH directions:

- Two produced false *survived* results — one changed an object field but not the local
  variable set on the next line; the other left the `try/catch` in place while claiming
  to remove listener isolation. Corrected, both were killed.
- One produced a false ***killed*** result. The unresolved-parent
  mutation did not compile (dropping the `continue` leaves `parentRect` possibly
  undefined at the deref), so jest exited non-zero having run **zero tests** — and the
  harness read any non-zero exit as "a test caught it". Mutated validly, by restoring
  the exact pre-fix code, it **survived**: nothing protected that guard. A test was added.

> **Harness rule:** a mutation run must assert that the suite actually RAN. Treat
> `Tests: 0 total`, or a non-zero exit with no failure count, as **unverified** — never
> as a kill. A false *survived* prompts investigation; a false *killed* is silent, and
> is the one that leaves a guard unprotected while looking green.

**Milestone 2 pass — 6 guards, 1 survivor, closed.** The auto-layout guards were each
weakened and the suite re-run: the dirty-ripple (`expandDirtyForLayout`), the reparent
and delete dirty-reporting, the `MoveTool` laid-out-child guard, the load-path
`layoutError`, and the flex-stack `gap` math. Five were killed immediately (2–3 tests
each). One **survived**: disabling `ReparentNodeAction`'s old-parent reporting broke
nothing — the 300-op fuzz, by chance, never reparented a child *out* of a multi-child
container at this seed, and there was no targeted test. A deterministic
reparent-out (and a matching delete) test was added; both now kill it. This is the whole
point of the discipline: **a fuzz is a sampler, not a proof of coverage — a survivor is
a missing test even when everything is green.** Two mutation attempts also reproduced the
"does not compile → `Tests: 0 total`" trap (a short-circuited `&&` un-narrows the
variable on the next line); per the harness rule they were re-authored to compile before
being trusted.

**Intrinsic-sizing pass — 5 hug guards, all killed.** Each weakened one at a time:
(1) the climb continuing only while hugging — reduced to one level → killed by the 3-deep
chain + pending-hug tests; (2) adding the first fixed container **before** the hug check
(so it's never added) → killed by 5 tests; (3) the measure fold ignoring children → killed
by 5; (4) dropping the pending→seed union → killed **only** by the deterministic
pending-hug test (the fuzz passes `pending=null`); (5) measure ignoring pending sizes →
killed by 2. Notably the one-level mutation (1) **survived the fuzz** — this seed never
builds a 2-deep hug chain with a bottom resize — and was caught only by the pinned
deterministic chain test, the same fuzz-is-a-sampler lesson as the M2 reparent-out gap.
The one-level and add-order mutations again hit the unreachable-code `Tests: 0` trap and
were re-authored to compile before being trusted.

**Flex-grow pass — 4 guards, all killed.** (1) not applying the distribution → killed by
3 tests; (2) dropping the `free > 0` guard so an overflow would shrink to a negative size
→ killed precisely by the overflow test; (3) moving the `grow` validation *after*
`layoutError`'s no-container early return (so a `{grow:-1}` patch with no container slips
through) → killed by the write-path test, which deliberately validates a container-less
patch; (4) `layoutContainerPass` dropping the child's `grow` → killed by the integration
tests (the pure `layoutChildren` unit tests still pass, since they feed `grow` directly).

**Adversarial agent review found one real bug the fuzz could not.** A multi-lens review of
flex-grow confirmed a preview-only defect: a **pending resize of a grow child** was
double-applied — the pending width fed the measure pass (so the child grew *past* it),
then the position-pass override clamped it back, leaving a gap before its sibling. The
`incremental === full` fuzz cannot see it (the override is in the shared path; the fuzz
passes `pending=null`), and the one prior pending-resize test used a non-grow child where
the override is a coincidental no-op. Fixed by having a pending patch on a laid-out child
preview **position only** (its size is already the layout's result); a regression test
proves preview == commit and fails without the fix. The review pass itself also perturbed
the working tree and dropped the `grow` wiring in `layoutContainerPass`; the same new test
caught that too. *Lesson: an agent review catches semantic/interaction bugs the property
fuzz is structurally blind to — but re-run the full gate afterward, because the review can
disturb the tree.*

**Grid pass — 5 guards, all killed, one gap surfaced.** Weakened: (1) auto-flow row
placement (all items in row 0) → killed by 2 tests; (2) `fr` tracks getting no share →
killed by 2; (3) `isLayoutContainer` not recognising a grid → killed; (4) the
mutual-exclusivity clearing in `applyMutations` → killed; (5) the `TrackSize` `fr > 0`
check → killed by the write-path test. Guard (3) was initially killed **only** by its unit
test — the delete-reflow test reports the parent directly (no climb), and `px`-row grids
don't resize on count — so mutation testing exposed a missing case: an `fr`-row grid's
heights depend on the item count, so **adding** an item (which reports only the new node)
must reflow existing rows via the climb. A deterministic `incremental === full` test was
added and now co-kills the mutation — the same "a survivor is a missing test" lesson.

**Constraints pass — 4 guards, one survived (a defensive gate), pinned.** Killed
immediately: the reference delta (`d = C − R` → `d = 0`, killed by the per-mode math + both
source tests), the `constraintRef` auto-capture, and the `layoutError` mode check. The
`!isLayoutContainer` gate **survived** — a valid container child has `computedLocal` and
never reaches the constraint branch, so no test exercised the gate (it only fires for a
damaged tree: a child claiming a container parent that does not list it). Added a
deterministic damaged-tree test (the child stays static, not repositioned to the container's
box) that now kills it — the gate is defensive but no longer unprotected.

**Constraints adversarial review — math clean, one write-path bug.** A read-only review
(a reference reimplementation matched `resolveConstraints` over 30,375 mode×size cases;
400+ constraint-heavy fuzz seeds with transforms and pending overlays found no
`incremental === full` divergence; all five design claims held) confirmed one medium
defect: the `constraintRef` auto-capture guard inspected only the incoming patch, so a
**second** constraints edit (a mode change, or an M5 inspector setting the two axes in
separate patches) re-captured the reference from the parent's *current* size — un-freezing
it, zeroing the delta, and teleporting the anchored child back to its rest position, which
undermines the whole frozen-reference model. Fixed by capturing only on **first** opt-in
(when the node has no existing `constraintRef`); an explicit ref in the patch (a deliberate
re-baseline) still wins. A regression test was proven to fail on the unfixed code.

**Margins + absolute pass — 5 guards, all killed.** Weakened: margin dropped from
positioning (killed by the flow-math test), absolute not excluded from the flex flow (2
tests), absolute not excluded from the hug measure, the constraint gate's `|| isAbsolute`
allowance (the absolute-can-be-constrained test), and `MoveTool`'s `&& !isAbsolute` (the
absolute-draggable test) — each killed by its targeted test. Both features degrade to the
pre-M2 behaviour when absent (in-flow / margin 0), so every existing test was byte-identical.

**Margins + absolute adversarial review — the margin math and absolute exclusion held (400×400
fuzz clean, every axis cross-checked); ONE high bug found.** Letting an absolute child of a
container be constrained exposed a latent flaw: `UpdateNodeLayoutAction` auto-captures
`constraintRef` from the parent's STORED size while `resolveConstraints` positions against
its COMPUTED size. Fine for a plain static parent (equal), but a container's computed size
routinely differs (hug), so a badge pinned to a hug-card corner flew off at rest (`x = 0 +
(50 − 400) = −350`). The fuzz was blind (both paths share the frozen ref and agree on the
wrong value); the one absolute+constraint test used a *fixed* container, sidestepping it.
Fixed by skipping the auto-capture for **container** parents (their stored size is an
unreliable reference — that capture is the M5 tool-layer's job, from the computed size); an
explicit ref still activates it. Regression test proven to fail on the unfixed code.

**Grid adversarial review — found TWO real bugs the fuzz was blind to.** A read-only
multi-lens review (100k random grids and 400 fresh fuzz seeds found the cell math and all
five design claims clean) confirmed two high-severity defects, both preview/edge-only so
`incremental === full` never diverged: (1) **resizing a grid item teleported it to its
ignored stored x/y** — the earlier "laid-out child previews position only" fix guarded
size but *leaked* position, and the resize tool's pending patch carries stored-based x/y;
fixed by having a laid-out child ignore a pending patch **entirely** (its whole rect is the
layout's result — size already folded through measure), with a regression test. (2) a
**transaction merging a container-set and a grid-set on one node dropped BOTH** layouts —
the merged delta held both and the post-hoc "clear both" in `applyMutations` cleared both;
fixed by carrying grid⊕container exclusivity **in the delta** (`UpdateNodeLayoutAction`
sets the other field to `undefined`), so the field-by-field transaction merge is last-wins.
Both regression tests were proven to fail on the unfixed code. *Reinforces: the property
fuzz cannot see a bug that is uniformly wrong across incremental and full — an adversarial
review can.*

### Fixture design: the assertion must be able to SEE the mutation

Across the paint modules, roughly ten of every mutation survivor had the same cause, and it
was never a missing assertion — it was a **fixture in which the mutation makes no
difference**. The test asserted the right thing about a case that cannot distinguish the two
behaviours. This is worth stating as a rule because it is cheap to apply *before* writing the
fixture and expensive to discover afterwards.

Observed shapes, each with the module it actually bit:

| Blind fixture | What it hides | Where |
|---|---|---|
| A **square** buffer, surface or grid | `width` ↔ `height`, row stride ↔ column stride, a transposed index | `Symmetry` (survived), `PixelBuffer`, `PixelPatch`, `Palette` |
| An **odd-only** (or even-only) size | the centre column/row case, and the de-duplication that depends on it | `Brush`, `Symmetry` |
| A **blank** "before" region | anything that reads the prior state — a patch that overwrites vs. one that composites | `PixelPatch` |
| **Equal error magnitudes** across compared candidates | a weighting, a tie-break, a channel drop | `Quantize` |
| A candidate placed **far away** in the compared space | "skipped" vs. "considered and lost" | `Quantize` (transparent palette slot) |
| **Small or sequential** indices | a stride, an offset, a two-hop lookup collapsing to one | `Gltf`, `Palette` |
| A bound checked on **one axis only** | the other axis's bound being absent | `PixelBuffer`, `TiledMap` |
| A **blank or uniform** input document | anything order- or content-dependent | `TiledMap` |

The checklist, applied when the fixture is written:

0. **Is this fixture a state the system can actually REACH?** The one that costs most. A
   hand-built fixture can be perfectly self-consistent and describe a configuration no
   producer ever emits — and then every assertion about it is true and says nothing.
   `SurfaceSpace` was written against a fixture pairing an identity `world` matrix with a
   non-zero `local` origin; `computeGeometry` never produces that pairing (it puts the whole
   placement in `world` and draws from the origin — `RenderModel.ts:488`). The module
   double-counted the node's position, six mutants died correctly, all assertions passed, and
   the bug surfaced only when the tool was wired to a real document. **Where a fixture stands
   in for a producer's output, build one from the producer.**
1. **Is any dimension equal to another?** Square is the default and the default is blind. Use
   3×8, not 8×8.
2. **Is the "before" state blank?** If so the test cannot tell a write from a merge.
3. **Are the competing candidates distinguishable only by the property under test?** If two
   things differ in three ways, the assertion pins none of them.
4. **Would the assertion still hold if I dropped the term I am testing?** If yes, it is not
   testing that term. (In `Quantize`, dropping the blue channel made the original test pass
   *more* strongly.)
5. **Does one test carry the whole protection?** Note it — `copyRect`, `applyPatch` and
   `diffRect` are each killed by exactly one test.
6. **Is this code compiled by anything the gate runs?** The one place the answer was NO is a
   SHADER: `tsc` sees a string, esbuild sees a string, jest sees a string, and the first reader
   that knows the language is a GPU driver on somebody's machine. An identifier named `packed` — a
   reserved word in GLSL ES 1.00 — therefore turned the entire WebGL backend off for months while
   every test passed and the app drew the right picture through the Canvas fallback. The guard is
   `GLSL_SOURCES` plus a reserved-word scan (mutant `RW1`), and the general form of the question is
   worth asking of any string this project hands to another language.
7. **Does the fixture walk THIS branch, or one that looks like it?** The most repeated fixture
   failure in this codebase is not a wrong assertion — it is a fixture that never reaches the line.
   Five in one sitting (2026-08-10), each caught by a survivor and none by a test:
   - SQUARE CELLS (16x16) hid a half-cell offset that read the wrong axis. Terrain's are 16x8 now.
   - A grid with EVERY tile filled could not tell `some` from `every`, so the rule forbidding stored
     tiles on an autotiled layer was unguarded. One filled cell among five empties tells them apart.
   - Clicks that all landed MID-CELL could not see a half-cell error, because the floor is the same
     either way. One pixel inside a boundary can.
   - A layer differing in cell WIDTH left the HEIGHT check unexercised: the first check refused it
     and the second never ran.
   - A rotation test built from RECTANGLES never reached the tile branch, which writes its own
     attributes — so "a tile object states its rotation" was protected by nothing.
   The shape of the question: when a branch writes its own output, the fixture has to walk *that*
   branch, not a sibling that resembles it; and when two checks guard one line, each needs an input
   the other would let through.
8. **Does the assertion state the RULE, or just accept the output?** A test can be true of every
   implementation and still be worthless. `rotatedTable`'s entries were checked with "this
   flip lands on the right mask" — which holds for ANY search order, because every one of the
   sixteen masks has more than one valid flip and masks 0 and 15 accept all eight. A mutant
   reversing the search survived a full battery (AT9, 2026-08-11). The rule is that the
   SMALLEST valid flip wins, so the least-turned tile does; stating that kills it, and stating
   it as a property rather than as sixteen pinned literals survives the class order changing.
   The question generalises: if you can imagine two different implementations both passing,
   the assertion is describing a symptom rather than the rule.
9. **Is this code REACHED by anything the app runs?** The sibling of question 6, and it has the same
   signature: a green test over code nothing calls. Escape's cancel was the case (2026-08-10). Seven
   tools implement an Escape branch — rotate, resize, marquee, move, pen, pixel-selection, the tile
   rectangle — and *not one of them could be reached*, because `App` resolved the DESELECT shortcut
   first and `deselect` stands aside only when nothing is selected, while a gesture that can be
   cancelled always has a selection: it needed one to start. Every unit test passed; the feature had
   never worked. Found by driving the real app, then by instrumenting: the tool was seen receiving a
   plain `q` mid-gesture and never receiving Escape.
   Three of those tests could not have caught it for a second reason worth naming — their fixture
   passed an event object with **no `preventDefault` at all**, so "did the tool claim the press"
   was not a question the fixture could ask. The guard is now behavioural (a counting
   `preventDefault`) plus a structural sweep of `editor/tools` for an Escape branch that never
   claims, so the next tool with a dead cancel fails the suite rather than the app.

This is checked, not asserted. **`npm run mutate:dimensions`** (`scripts/mutate-dimensions.js`)
runs the dimension-confusion family — and its neighbours, the mutations any *convenient* fixture
cannot see — over the paint modules, the Tiled reader, the mesh, nine-slice, the tile grid, the tile
brush and the autotiler, exiting non-zero on a survivor: currently **215 mutants, 215 killed**
(full run 2026-08-12 at 1,734 tests: **56m20s, 16s per mutant**, nothing NOT APPLIED and nothing AMBIGUOUS). The exporter's ten are
checked by the ROUND TRIP: a real map imported, exported and imported again, compared cell by
cell — so a mutation has to survive a reader that was written against files Tiled itself wrote.
Six cover `SurfaceSpace`, where the convenient fixture is not
a square buffer but **a box at the origin** (which hides a dropped origin term) and **a
round-trip-only assertion** (which hides a half-pixel shift, because it shifts both directions
equally). Three cover `TiledMap`, where it is **a map that offsets only one axis** (so a swap is
invisible), **a map that always states the attribute** (so a missing default is invisible), and
**a corpus where only one render order ever occurs** (so an inverted condition is invisible —
all 20 maps in the tree use `right-down`).

**WATCH IT IN A BROWSER TAB.** Every run writes `%TEMP%/vde-mutation-progress.html` — a bar, the
count, elapsed, an ETA and the last forty verdicts — rewritten after each mutant with a
`<meta http-equiv="refresh">` in its head, so the tab reloads itself. No server and no
dependency: `fetch` against `file://` is blocked, which rules out the obvious poll-a-JSON
design, so the state is baked into the document instead. It prints its own last-updated time,
which is what distinguishes a run that DIED from one that is merely slow. `MUTANT_POPUP=1`
opens it automatically; a background run should not throw a window at anybody, so that is opt-in.

**A KILLED RUN HEALS ITSELF ON THE NEXT ONE.** The restore lives in a `finally`, which a hard
kill skips — so an interrupted run used to leave a MUTATED source file in the working tree. That
happened twice in ten minutes on 2026-08-11, once leaving `node.tilemap = node.tilemap` in the
tilemap write path and once `width - 1 - y` in the vertical mirror; both compile, both are
wrong, and both would have been committed by anyone who did not check `git status`. The original
is now written to `%TEMP%/vde-mutation-pending.json` BEFORE the file is touched and cleared
after, and the next run puts back whatever it finds — **before** the dirty-tree check, because a
leftover mutant makes the tree dirty and a restore placed after that check could never fire.

**RUN THE PRE-FLIGHT AFTER ANY REFACTOR: `MUTANT_CHECK=1 npm run mutate:dimensions`.** It answers
one question — does every mutant's `from` still match its file, exactly once? — in about a second,
with no tests run at all. Until 2026-08-10 the only way to learn that a `from` had drifted was a
full battery, which is nearly an hour now, and that is backwards: `NOT APPLIED` is the verdict a
REFACTOR causes, so the moment to look is right after the refactor. Deriving `cellAt` from a new
`cellCoordAt` and `terrainCellAt` from `terrainCoordAt` moved five mutants' lines out from under
them (`TE4`, `TE5`, `TT2`, `TB1`, `TB2`) — found in one second, and all five re-authored and
killing before the change was committed. Three earlier ones (`TT2`, `SS5`, `RW2`) had each been
discovered the slow way.

**AND A FOURTH: `AMBIGUOUS`.** A `from` that appears TWICE in its file mutates whichever site
comes first, because `String.replace` takes the first — so the mutant silently tests a line its note
does not describe. Added 2026-08-10 after reading Tiled's object layers gave
`visible: a.visible === undefined ? ...` a second home: `TM4` re-aimed from a tile layer to an
object and went on reporting a kill, for a guard nothing was testing any more. Four mutants were
mis-aimed by that one change. Both this and `NOT APPLIED` exit non-zero.

**A CONTROL CHARACTER IN SOURCE is a lint error** (`npm run lint`), and it is there because nothing
else in the gate can see one: `tsc` compiles it, esbuild bundles it, jest runs it, and a terminal
renders it by ERASING the character before it, so the file reads correctly on screen while meaning
something else. On 2026-08-10 a word-boundary escape reached a regex as a literal 0x08 through a
shell heredoc, turning a pattern that matches every object tag into one that matches nothing — and
the reader then found zero objects in a file holding 114, with every test still green. Tab, newline
and carriage return are the only control characters a source file may contain; a deliberate one (a
NUL joining cache-key fields) is written as an escape so it is visible and so this check can tell it
from an accident.

**THERE IS A THIRD VERDICT, and it is the one that has actually cost guards.** `NOT APPLIED` means
the mutation's `from` matched nothing, so the mutant tested NOTHING while the run still summarised as
a pass — five guards were lost to it across two sittings. Three of those were **line endings**: every
`from` is written with `
`, so a two-line mutation matches a file newly written in the working tree
and stops matching the same file once a checkout turns it CRLF (this tree holds both kinds). The
matcher now normalises before matching. The other two were mutations "simplified" into a shape that no
longer appeared in the source. Read every `NOT APPLIED` as a missing guard.

**AND THE BATTERY ITSELF IS NOT LOADED BY THE GATE.** A syntax error in `scripts/mutate-dimensions.js`
once passed `npm run check` and `npm run lint` and was committed — the battery then died on require,
which is a tool reporting nothing rather than a tool reporting a problem. `check-module-headers` now
compiles every `.js` under `scripts/` (with `vm.compileFunction`, which compiles without executing).

It found the first survivor — `Symmetry`'s vertical axis reading
`width`, which survived all 1292 tests because every fixture but one was 8×8, and that one
exercised the horizontal axis only. It is not part of `npm run check` (it runs the suite once
per mutant, so it costs minutes rather than seconds) and it **refuses to run on a dirty tree**,
because it edits real source files and restores them.

A mutation whose `from` no longer matches is reported as **NOT APPLIED** and counted as a
failure, not skipped — the code moved out from under it and the battery is testing nothing.

## Doc-staleness tripwire (`npm run doc-drift`)

Each doc that describes specific code declares it in the doc itself:

```html
<!-- describes: src/core/actions, src/core/document/Serializer.ts -->
```

`scripts/check-doc-drift.js` flags a doc when any declared source has been **committed
to since the doc was last committed to**. Clearing the flag means committing the doc —
which is the re-read it exists to force.

It cannot tell you prose is wrong; nothing can. It targets the failure that actually
occurred: editing one section and never re-reading the rest, so drift accumulated where
nobody was looking.

**Ancestry alone passed a lie, so there are two more checks.** A doc committed a dozen
times still carries whatever banner nobody re-read: five of the seven stamped docs said
`schema v63` against a live 66 and every one was green. So a doc that *states* the schema
version must state the current one, read from `SCHEMA_VERSION` rather than restated here.
`schema vNN` is the stamp; `schema NN` without the `v` is a historical citation — the docs
make those constantly and correctly, and flagging them would be noise, which is what gets
switched off.

**And it refuses to pass vacuously, in two ways**, because the failure mode of a
pattern-matching check is matching nothing and reporting that all is well. A doc with a
frozen banner and no stamp is reported. So is a watched doc that declares no `describes:`
at all — `MILESTONES.md` and `PLANNED-FIXES.md` were both named in the script and neither
had a directive, so for its whole existence it looked them up, found nothing and moved on
without a word. They sat three weeks at a status line with **seven** milestones marked
not-started that had shipped. Being skipped is indistinguishable from passing.

All three conditions are verified by reintroducing them against the live tree and watching
each fire: a stamp reverted to v63, a `describes:` deleted, a stamp removed from a banner.

**Measured on first run against real history — 3 flags, 2 true positives:**

| Doc | Verdict |
|---|---|
| `API-CONTRACTS.md` | **true** — `migrateIfNeeded` had become a public export and was undocumented |
| `DOCUMENT-SCHEMA.md` | **true** — still described `version` as `= CURRENT_VERSION on new docs`; it is `SCHEMA_VERSION`, plus a stale `migrateIfNeeded` signature and a hand-written `NodeType` |
| `ARCHITECTURE.md` | **false** — its history claims were still accurate |

The `DOCUMENT-SCHEMA` case is the point: `CURRENT_VERSION` still *exists*, so no
identifier check could see it, and it is prose, so the API pin could not either. The
freeze rule had already missed it once. The tripwire caught it only by forcing the
re-read — which is the whole design claim.

**Not in `npm run check`.** It is noisy by construction: every source commit flags its
doc whether or not the doc is wrong, and the flag clears only on a doc commit. Adding it
to the gate is one line in `package.json`; that is a workflow-cost decision, not a
correctness one.

## Regression discipline

When fixing a bug, add a test that **fails on the unfixed code and passes after**. Example
this project follows (R2, the undo/history aliasing bug): the fix in
`hydrateDocument` was temporarily reverted to confirm the new test failed with the exact
corruption signature (`Expected 0, Received 50`), then restored so it passes. A regression
test that was never seen to fail proves nothing.

## Gaps / not yet automated (tracked, not silently ignored)

- **Renderer & tools** have only the beginning of automated **DOM** coverage. `emitSVG.test.ts`
  drives the emitter through a ~40-line FAKE DOM (attributes, children, the two `:scope >`
  selectors it uses) — the same move `emitCanvas.test.ts` made with a mock context. It exists
  because a real regression shipped that 1312 tests could not see: a raster's identity key was set
  as an `<image>` href, so a painted canvas was invisible on the DEFAULT backend. Beyond that: the renderer's pure model is
  unit-tested (`RenderModel.test.ts`), but the `emitSVG` backend, the `renderSVG`/
  `renderCanvas`/`renderScene` shims (canvas sizing, DPR, the backend switch), and the DOM
  plumbing of the move/draw tools are validated by browser smoke tests. Tool *logic* that is DOM-free
  is node-tested with fake events — the viewport math (`panBy`/`zoomAt`/`screenToWorld`),
  the `ToolController` pan-mode intercept, its **DOM-free corner-resize AND rotate** (handle
  picked by `handleAtPoint`; resize drives geometry, rotate spins about the AABB centre and
  live-commits a coalesced transform = one undo per continuous drag), the `SelectTool` marquee (drag →
  `nodesInRect`, click-to-select, shift-additive), and **alignment snapping** (`computeSnap`/`snapPoint`/
  `guidesForRect`/`snapTargetsExcludingSubtree`, with the MOVE drag and the corner-RESIZE both folding it in
  for a single top-level node). Adding jsdom-based emitter/tool tests is future work.
- **The interface shell** (workspace tabs, the tool strip, the options row, the menu) has no
  automated coverage and was verified by DRIVING THE RUNNING APP over CDP — element rects read
  back per tool and per workspace, because the faults it fixes are geometric: the canvas moved
  27px when a tool was chosen and 11px when a workspace was. The one thing pinned in the suite is
  a source assertion that `detachInstance` calls `validate()` BEFORE dispatching, which replaced
  an older pin on the disabled Detach button when that button moved into the Edit menu.
- **Electron main/preload** IPC is not unit-tested (thin, and requires an Electron host).
  The Open → edit → Ctrl+S round-trip in particular is only manually verified.
- `applyMutationsToDocument`'s `text` / `src` / `name` branches have no producing Action
  yet, so they are reachable only by constructing a delta directly — currently untested.
- The same-node `TransactionAction` merge path is exercised indirectly but never
  asserted on directly.
- `ComputedState` carries geometry only. Resolved style (M5 tokens) and layout output
  (M2) are not in it yet, so neither has coverage here.

## Conventions

- Test file mirrors the module and tags each `describe` with the requirement/fix id it
  satisfies (e.g. `T2`, `M24`, `R2`).
- Prefer the small factory helpers (`createDocWithRectangle`, `createDocWithParentChild`)
  over ad-hoc fixtures.
- Mock browser globals (e.g. `localStorage`) locally within the `describe` that needs them.
